# 2000 DAYS · 星球来信

一个蓝紫色、奶油白的小宇宙，为两个人的 2000 天留下一份礼物。

当前交付是**第一阶段：视觉框架**。8 个场景、统一视觉系统、响应式页面和场景导航已经建立，可以按故事顺序浏览，也可以切换场景。答题验证、邀请函解锁、照片旋转与放大、流星雨情话、气球 DIY 与本地保存、扭蛋抽取、情书打字机、贺卡翻页、音频播放、烟花和贺卡导出将在后续互动阶段实现。当前画面中的展示元素不代表这些交互已完成。

## 本地运行

需要 Node.js 22.12+ 或 24 LTS，以及 npm。本次在 Node.js 24 中完成验证。

```bash
npm ci
npm run dev -- --host 0.0.0.0
```

Vite 会在终端显示开发地址。开发时直接使用现有检出目录，无需创建 Git worktree。

```bash
npm run typecheck  # TypeScript 检查
npm run build      # 类型检查并构建静态文件到 dist/
npm run preview -- --host 0.0.0.0  # 预览生产构建
```

页面底部星轨支持直接切换八个章节，右上角“旅程目录”支持键盘操作和 Escape 关闭。地址中的 `#memories`、`#final` 等可直接定位章节；当前阶段不会启用答题门禁。

## 换成你们的真实素材

没有提供真实素材时，页面只使用抽象图形和明确标记的占位内容。不会生成或编造情侣照片、恋爱经历与语音。把自己的文件放进以下目录，也可在数据文件中改成其他本地图片路径。

**本阶段已接入木马场景的前两张照片和最终贺卡旁的合照。** 放入 `memory-01.jpg`、`memory-02.jpg`、`final-photo.jpg` 后，重启开发服务或重新构建即可替换对应占位。其余 10 张已预留数据，完整的照片旋转、轮播、详情将在下一阶段接入。缺图时保留占位框，不会请求不存在的素材；不使用虚构情侣照补位。

```text
public/
├── images/
│   ├── memory-01.jpg       # 共 12 张，从 01 到 12
│   ├── memory-02.jpg
│   ├── …
│   ├── memory-12.jpg
│   ├── final-photo.jpg     # 最终贺卡合照
│   └── optional-background.jpg # 预留的自定义背景，当前不自动使用
├── audio/
│   ├── bgm.mp3             # 背景音乐，等待互动阶段接入
│   └── voice.mp3           # 你亲自录制的语音，等待互动阶段接入
└── fonts/                  # 可选本地字体
```

在代码中，`public/images/memory-01.jpg` 对应 `/images/memory-01.jpg`。目前素材发现支持 `public/images/` 第一层的 JPG、JPEG、PNG、WebP、AVIF 文件。建议照片使用压缩后的 JPEG 或 WebP，保留适合手机浏览的分辨率；若改为 WebP，同时更新配置路径。不要把 `public` 写进浏览器使用的资源路径。

MP3 目前仅预留路径。后续语音播放器会由用户主动点击播放，背景音乐和语音分别控制，不自动播放，也不会使用 AI 语音。请使用有权使用的照片和音乐。

## 部署

这是一个纯前端静态网站，不需要后端或数据库。

### 推荐：使用现有 GitHub 仓库免费发布

不需要额外注册 Vercel、Netlify，也不需要购买域名。仓库已包含 `.github/workflows/deploy-pages.yml`，通过 GitHub Actions 自动构建与发布。

首次发布：

1. 将完整项目提交并上传到 `fujiayi425-netizen/Public` 仓库的 `main` 分支；不要上传 `node_modules/` 或 `dist/`。
2. 在 GitHub 仓库中打开 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 在 **Actions → Publish our little universe → Run workflow** 中选择 `main` 并运行。如果首次上传时 Pages 尚未启用而导致运行失败，设置完成后重新运行即可。
4. 等待 `build`、`deploy` 两个任务成功。以 GitHub Pages 设置页或部署任务输出显示的网址为准，再用电脑或手机打开。

后续更新个人素材和文案后，上传到 `main` 会自动重新发布。工作流从 Pages 配置读取站点子路径，构建脚本会正确处理 `/Public/` 下的资源。

**当前云端开发地址与文件路径不是公网网址。** 完成 GitHub 上传、Pages 设置和成功部署前，手机无法通过它们访问网站；保存云环境配置也不会发布网页。

### 其他静态托管

1. 运行 `npm ci` 和 `npm run build`。
2. 将 `dist/` 内容部署到任意 HTTPS 静态托管服务。
3. Vercel / Netlify 可使用构建命令 `npm run build`，输出目录 `dist`。
4. 根域名部署可使用默认设置。部署到子目录（例如 GitHub Pages）可运行 `npm run build -- --base=/Public/`，按实际路径替换 `/Public/`。当前本地图片通过 Vite 解析 URL，保留配置中的 `/images/...` 即可；后续接入 MP3 时，需通过 `import.meta.env.BASE_URL` 解析音频前缀。
5. 部署前用 `npm run preview` 检查生产构建，并在手机上检查文字、照片比例和页面滚动。

前端答题是未来的仪式感互动，不是真正的身份验证。部署后的前端代码和静态资源可能被访问者读取；不要在其中存储密码、密钥或不希望公开的隐私。需要私密访问时，应使用托管平台的访问控制。


如果环境中已有 `/usr/bin/chromium`，测试会直接使用它。测试运行时会自动启动开发服务，或复用已运行的 5173 端口。
